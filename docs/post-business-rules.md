# 모집글 핵심 비즈니스 규칙 — 기능정의서 기준 정리

기준: 기능정의서 v1.1, 2026-09-24 및 PM의 ERD v4 피드백. 갱신일 2026-10-12. POST-001~008, DISC-001~005, JOIN-001~008, COORD-001~004, REPORT-001~004, ADMIN-003, 6·8·9장.

이 문서는 모집글의 사용자 동작과 데이터 정합성 규칙을 정리한다. HTTP 상태 코드, DTO, 잠금 구문, 물리 테이블 구성은 각각 API·구현 명세에서 관리한다.

## 1. 공통 정의

| 용어 | 규칙 |
|---|---|
| 모집 유형 | TAXI 또는 DELIVERY, 생성 후 변경 불가 |
| 모집 작성자 | POST.author_id로 식별하며 PARTICIPATION을 생성하지 않음 |
| 기준시각 T | TAXI는 출발시각, DELIVERY는 주문마감시각 |
| 현재 인원 | 1(작성자) + JOINED PARTICIPATION 수 |
| 정원 | TAXI 2~4명, DELIVERY 2~10명. 작성자 포함 |
| 시간대 | Asia/Seoul. 입력과 동시간 비교는 분 단위, 시간 경계 판정은 실제 timestamp |
| 인증 | 목록·상세·작성·수정·참여·댓글·신고·마이페이지·관리자 기능 모두 인증 필수 |
| 검증 책임 | FE는 즉시 피드백, BE는 저장·변경의 최종 검증 수행 |

## 2. 생성 — POST-001~003

- 인증된 사용자가 유효한 유형·필수값·입력 길이·유형별 정원을 제공해야 한다.
- 기준시각은 `referenceTime > currentTime + 10분`을 만족해야 한다. 정확히 10분 남은 시각은 생성할 수 없다.
- 정상 생성의 상태는 OPEN이고 현재 인원은 1명이다.
- 동일 작성자의 동일 기준시각 모집을 유형과 관계없이 차단한다. TAXI 18:00과 DELIVERY 18:00도 중복이다.
- 유효 모집은 실질 OPEN/FULL/CLOSED로 정의한다. 중복 비교에서 CANCELLED/FINISHED/REMOVED 및 삭제된 모집은 제외한다. DB가 OPEN/FULL/CLOSED여도 기준시각이 도달했으면 실질 FINISHED로 보고 제외한다. PM의 v4 피드백에 따른 최종 규칙이다.
- 기준시각은 분 단위로 통일한 값으로 비교한다. 다른 분 값이면 동시간 중복 조건에 해당하지 않는다.

## 4. 수정 — POST-004, 9.5 상태별 행동 원칙

수정 권한은 작성자 본인에게 있다. 기준시각이 도달해 실질 FINISHED인 경우도 수정할 수 없다. 생성 후 유형 변경은 허용하지 않는다.

| 실질 모집 상태 | 현재 JOINED 수 | 수정 범위 |
|---|---:|---|
| OPEN / FULL | 0 | 유형을 제외한 허용 필드. 기준시각 변경은 T+10 조건과 동시간 중복을 재검증 |
| OPEN / FULL | 1명 이상 | 제목·설명·외부 소통 링크 등 비핵심 필드 |
| CLOSED | 무관 | 비핵심 필드 |
| CANCELLED / FINISHED / REMOVED | 무관 | 수정 불가 |

FULL은 정상 데이터에서 정원이 충족되어 JOINED가 있으므로 비핵심 수정만 가능하다. 위 표는 상태 검사와 참가자 검사 기준을 함께 표현한 것이다.

핵심 필드는 다음과 같다.

- TAXI: 출발지, 목적지, 출발시각, 정원.
- DELIVERY: 음식점, 주문마감시각, 수령장소, 정원.

참가자 조건은 현재 JOINED 기록으로 판단한다. 취소 기록의 존재만으로 핵심 필드가 계속 잠기는 조건을 추가하지 않는다. 다만 CLOSED는 44쪽 상태별 행동표에서 비핵심 수정만 허용하므로 JOINED가 0명이어도 그 범위를 유지한다.

orderGuide는 정의서의 핵심 필드 목록에 포함되지 않은 선택 안내 필드다. 수정 DTO의 허용 필드를 구체화할 때 비핵심 안내로 취급하는 해석을 기록하고, 범위를 확대하면 관련 AC를 함께 갱신한다.

## 5. 참여·참여 취소 — JOIN-001~008

참여는 아래 조건을 모두 만족해야 한다.

```text
유효한 모집이 존재하고 삭제·취소·종료되지 않음
AND POST.status = OPEN
AND currentTime < referenceTime - 10분
AND currentUserId != authorId
AND 현재 본인 참여 상태 != JOINED
AND 1 + JOINED 참여 수 < capacity
```

최초 참여는 JOINED 기록을 생성한다. 취소 후 재참여는 같은 (post_id,user_id) 기록을 JOINED로 재활성화한다. id와 최초 created_at을 유지하고 updated_at을 갱신하며 cancelled_at을 NULL로 되돌린다. 다른 모집에 참여하는 것은 허용한다.

참여 취소는 본인의 JOINED 기록이 있으며 POST가 OPEN/FULL/CLOSED이고 `currentTime < referenceTime - 10분`일 때만 가능하다. 작성자는 참여 기록이 없으므로 모집 취소 기능을 사용한다.

현재 인원은 참여 성공 시 1 증가, 정상 취소 시 1 감소한다. 중복 신청·반복 취소·검증 실패는 인원이나 참여 시각을 추가 변경하지 않는다.

## 6. 상태 전이 — 6장, POST-005~008

| 현재 상태 | 조건·행위 | 다음 상태 | 처리 |
|---|---|---|---|
| OPEN | 참여 성공으로 정원 도달 | FULL | 추가 참여 차단 |
| FULL | T-10 이전 정상 참여 취소로 정원 미만 | OPEN | 재모집 가능 |
| OPEN / FULL | 작성자가 기준시각 이전 수동 마감 | CLOSED | 신규 참여 차단 |
| CLOSED | T-10 이전 정상 참여 취소 | CLOSED | 인원 감소, CLOSED 유지 |
| OPEN / FULL / CLOSED | 작성자가 기준시각 이전 모집 취소 | CANCELLED | 모든 JOINED 참여를 CANCELLED로 변경 |
| OPEN / FULL / CLOSED | 기준시각 도달 | FINISHED | 참여·취소·댓글 작성·외부 링크 차단 |
| REMOVED 제외 모든 상태 | 관리자 숨김 | REMOVED | 일반 목록·상세 비노출, 진행 중 참여 취소, 최소 이력 유지 |

수동 마감은 OPEN뿐 아니라 FULL에서도 가능하다. 수동 마감과 모집 취소의 허용 기한은 기준시각 이전이다.

위 표에 없는 상태 전이는 허용하지 않는다. CLOSED/CANCELLED/FINISHED에서 OPEN으로 임의 복귀할 수 없다. PARTICIPATION의 CANCELLED → JOINED 재참여는 모집 상태 복귀와 다르다.

DB 상태 갱신이 지연되더라도 서버는 기준시각 도달을 FINISHED로 판정한다. CANCELLED와 REMOVED는 시간 경과만으로 FINISHED로 바꾸지 않는다. DB 저장/조회 계산은 구현 선택이며, 현재 API는 조회·검증 시 계산을 선택했다.

OPEN 상태에서 T-10이 지나도 POST 상태는 OPEN일 수 있다. 이때 `joinable=false`이며 UI에는 “참여 마감”을 표시한다. 참여 마감을 별도의 DB 상태로 추가하지 않는다.

## 7. 시간 경계의 구분

| 행위 | 허용 조건 |
|---|---|
| 모집 생성 | T > 현재시각 + 10분 |
| 참가자 없는 모집의 기준시각 변경 | 새 T > 현재시각 + 10분 |
| 참여·재참여 | 현재시각 < T - 10분 + 나머지 참여 조건 |
| 참여 취소 | 현재시각 < T - 10분 + 본인 JOINED·활성 상태 |
| 작성자 수동 마감 | 현재시각 < T + OPEN/FULL |
| 작성자 모집 취소 | 현재시각 < T + OPEN/FULL/CLOSED |
| 완료 판정 | 현재시각 >= T |

T=18:00이면 참여·참여 취소는 17:49:59에 조건부 허용되고 17:50:00부터 차단된다. 작성자 수동 마감·모집 취소는 18:00 이전까지 가능하다. 서버 검증 시각이 기준이며 브라우저 시각이나 요청의 도착시각만으로 허용 여부를 결정하지 않는다.

## 8. 삭제와 이력 — POST-007, POST-008, ADMIN-003, MY-001~002

- 일반 작성자는 모집 취소를 사용한다. 물리 삭제 기능을 제공하지 않는다.
- 관리자 조치는 soft delete로 콘텐츠를 숨기고 운영·참여 이력을 보존한다.
- 기준시각 이전의 진행 중 모집을 숨기면 현재 JOINED 참여를 CANCELLED로 변경한다.
- 이미 FINISHED된 모집을 숨기면 최종 JOINED 이력을 변경하지 않는다.
- REMOVED는 일반 목록·상세·본문·명단·외부 링크에서 접근할 수 없다.
- 작성자·참가자 마이페이지에는 본문·장소·링크 대신 “관리자에 의해 삭제된 모집”이라는 최소 이력만 표시한다.

## 9. 조회·정보 공개 — DISC-003~004, COORD-004, 9.3

| 대상·상태 | 현재 인원 | 참가자 표시명 | 외부 링크 |
|---|---|---|---|
| 비참여 로그인 사용자 | 공개 | 비공개 | 비공개 |
| OPEN/FULL/CLOSED 작성자·JOINED 참가자 | 공개 | 공개 | 공개 |
| CANCELLED 참가자 | 공개 | 비공개 | 비공개 |
| FINISHED 작성자·최종 JOINED 참가자 | 공개 | 공개 | 비공개 |
| CANCELLED 모집의 작성자 | 공개 | 현재 JOINED 없음 | 비공개 |
| REMOVED 관계자 | 마이페이지 최소 이력 | 비공개 | 비공개 |

학교 이메일·학번·전화번호는 다른 일반 사용자에게 공개하지 않는다. ADMIN의 운영 조회는 필요한 목적과 최소권한에 맞춰 별도 관리한다. 외부 링크가 금지된 응답에서는 URL 값 자체를 반환하지 않는다.

모집 목록의 기본 정렬은 기준시각 오름차순이다. 기본 활성 탐색 목록은 OPEN/FULL만 포함하고 CLOSED/CANCELLED/FINISHED는 상태 필터 영역에서 노출한다. 완료 판정과 joinable 판정은 같은 서버 시각에 기반해야 한다. currentMemberCount/joinable은 DB에 저장하지 않는 서버 계산값이다.

## 10. 유사 모집 추천 — DISC-005

추천 대상은 동일 날짜·동일 유형·OPEN 모집이다. 핵심 문자열을 정규화한 뒤 완전 일치하고 기준시각 차이가 30분 이하인 후보를 표시한다. ±30분 경계를 포함한다.

- 정규화: 앞뒤 공백 제거, 연속 공백 1개로 축약, 영문 대소문자 무시.
- TAXI: 출발지와 목적지가 모두 일치.
- DELIVERY: 음식점명과 수령장소가 모두 일치.

추천이 있어도 새 모집을 작성할 수 있다. 동일 작성자·동일 기준시각의 생성 차단은 별도 규칙으로 계속 적용한다.

## 11. 댓글·신고와 상태의 연결

- 댓글 작성은 OPEN/FULL/CLOSED에서 가능하며 내용은 1~500자다. CANCELLED/FINISHED/REMOVED에서는 작성할 수 없다.
- 신고는 타인의 OPEN/FULL/CLOSED/CANCELLED/FINISHED 모집에 가능하다. 본인 글·REMOVED·중복 신고는 거절한다.
- 신고는 사용자당 모집당 1건이다. 사유는 정의서의 5개 ENUM이며 상세내용은 선택·최대 500자다.
- 신고 누적만으로 자동 REMOVED 처리하지 않는다. 관리자가 처리 여부를 판단한다.

## 12. 정합성 및 구현 명세의 경계

확정된 요구사항은 동시 요청에서도 정원·중복·상태·시간·권한을 일관되게 보장하고 실패 시 변경을 남기지 않는 것이다. 동일 모집의 참여·취소·수정·마감·모집 취소·관리자 숨김은 서로의 변경을 고려해야 한다.

현재 구현에서는 참여/상태 변경의 POST 잠금을 유지하고 모집 생성/수정에는 작성자 USERS → POST 잠금 순서를 적용한다. 잠금 획득 후 시각 확인, READ COMMITTED 쓰기 트랜잭션, PARTICIPATION 복합 UNIQUE, 조건별 CHECK를 사용한다. v4의 유효 모집 중복은 작성자 잠금 아래 검사/저장하고 기존 valid_reference_time 생성 열은 제거한다. 이는 확정된 기능 규칙을 보장하기 위한 구현 선택이다. 다른 동시성 제어 방식도 같은 결과를 보장해야 한다.

## 13. 핵심 Acceptance Criteria

- 정상 생성 결과가 OPEN·1/capacity다.
- 생성 및 기준시각 변경 시 정확히 10분 남은 값은 거절된다.
- 동일 작성자의 같은 분 TAXI/DELIVERY 동시 생성이 차단된다.
- JOINED가 있는 모집의 핵심 필드 변경과 CLOSED의 핵심 필드 변경이 거절된다.
- 마지막 자리 경쟁에서도 현재 인원이 정원을 넘지 않는다.
- 정확히 T-10의 참여·참여 취소는 실패하며 기존 데이터가 유지된다.
- FULL 취소는 OPEN, CLOSED 취소는 CLOSED를 유지한다.
- 기준시각 이전 작성자 모집 취소가 모든 JOINED를 CANCELLED로 변경한다.
- 기준시각에 도달하면 저장 status와 무관하게 활성 모집이 FINISHED로 표시된다.
- 진행 중 관리자 숨김은 참여를 취소하고 종료된 모집의 최종 참여 이력은 유지한다.
- 참가 취소 또는 모집 종료 후에는 정책에 맞춰 명단·외부 링크의 노출이 즉시 달라진다.
- 유사 모집 추천은 ±30분을 포함하며 추천 자체가 작성을 차단하지 않는다.
