# 새 저장소 통합 검증 기록

검증일: 2026-10-12. 대상: SYU-Taxi-Delivery/taxi-delivery-sharing, Spring Boot 4.1.1 / Gradle 9.7.1.

| 검증 | 결과 |
|---|---|
| 기본 Gradle test / H2 | 모집글 39 + Participation 48 + 학교 세션 연결 7 + 기존 사용자/컨텍스트 4 = 98개 통과 |
| 전용 MariaDB 11.4.10 / InnoDB | 모집글 39 + Participation 48 = 87개 통과 |
| Flyway 신규 사용자 V1 / 모집글·참여 V2 | 전용 신규 스키마에서 적용 성공 |
| Hibernate validate | 팀 User/UserAuth/LocalCredential/RefreshToken 및 모집글·참여 매핑 검증 성공 |
| Gradle bootJar | 실행 가능한 JAR 생성 성공 |
| 최종 실행 JAR 실제 HTTP | 모집글 smoke와 기존 Participation smoke 모두 통과 |
| MySQL 8.4 Testcontainers | Docker 미설치로 미실행. `gradlew mysqlTest` 실행 경로 제공 |

기본 test에서는 외부 DB 계약 87개가 환경변수 미설정으로 skip된다. 외부 DB를 연결한 별도 실행에서 해당 87개를 모두 수행했다. 두 DB의 성공 합계는 185회이며 MariaDB를 MySQL에서 실행한 결과로 간주하지 않는다.

모집글 계약은 유형별 입력, 작성자 포함 인원, +10분과 분 단위 시간, 유효 모집 중복, 작성자 권한, 참가/마감 상태의 핵심 조건 수정 제한, PATCH 생략/null, JSON 타입/중복 키, 정보 공개, 실질 FINISHED, 목록 필터·정렬·페이지 및 동시성 잠금을 검증한다. Participation 계약은 마지막 자리 경쟁, 중복 신청, 취소/재참여 ID 유지, 목록 권한, 모집 취소/삭제 경합, DB CHECK 실패 시 롤백을 검증한다.

학교 세션 연결은 메일 발송을 mock으로 대체하고 기존 이메일 가입 → 로그인 → 실제 User ID로 모집글 작성, 로그인 실패 횟수/5회 잠금, CSRF, 비활성 계정 차단, ID 위조 입력 거절, 세션 ID 교체/로그아웃, 로그인 후 계정 정지 시 접근 차단을 검증한다. 실제 SMTP 발송 및 별도 학교 SSO 공급자 연결은 검증하지 않았다.

기존 팀 사용자 코드를 유지하면서 컴포넌트/엔티티/저장소 스캔과 PasswordEncoder를 연결했다. 기존 데이터가 있는 공유 DB는 신규 DB와 달리 별도 스키마 대조와 baseline 절차가 필요하다. [실행 안내](running.md)를 참고한다.

실제 HTTP 모집글 검증은 작성 → 비참가자 상세/소통 링크 비노출 → 수정 → 참여/인원 반영 → 핵심 조건 수정 409 → 중복 생성 409 → 유형 목록 → 취소/링크 차단 순서다. Participation 검증은 참여 → 상태/명단 → 취소 → 명단 권한 차단 → 재참여 시 기존 ID 유지 → 내역 조회 순서다.

## 2026-10-15 기준시각 재검증

수정 API의 기준시각 조건을 확인하고 경계/비핵심 수정 테스트 8건을 보강했다. H2 모집글 테스트 47건이 모두 통과했다. 운영 코드와 트랜잭션/잠금 정책은 변경하지 않았다. [확인 내용 및 테스트별 결과](revalidation/reference-time-2026-10-15.md)를 참고한다. 위 2026-10-12의 전체·외부 DB 결과와 구분되는 로컬 재검증이다.

## 2026-10-15 동시성·트랜잭션 재검증

상위 트랜잭션의 오래된 JPA 엔티티가 잠금 후 재사용되는 문제를 실제 MariaDB에서 재현·수정했다. 부모 POST 잠금 아래 최신 상태 조회와 쓰기 트랜잭션 조건을 보강했고, DB 제약 실패 시 양쪽 테이블 롤백을 확인했다. 최종 H2 전체 131건, 전용 MariaDB 전체 120건이 통과했다. [재현 사례·수정 내용·광빈님과 공유할 통합 계약](revalidation/concurrency-transaction-2026-10-15.md)을 참고한다. 이 변경은 아직 로컬에 있으며 새 GitHub CI/MySQL 8.4 검증은 수행하지 않았다.

## 2026-10-15 모집 중복 방지 재검증

생성과 기준시각 변경이 같은 작성자 잠금을 유지하는지 실제 InnoDB 락 대기로 검증했다. 유형 조합, 처리 순서를 고정한 생성/수정 경합, 실질 FINISHED 제외 등 테스트 24건을 보강했다. 이번 항목에서 운영 중복 방지 로직은 변경하지 않았다. 누적 H2 전체 155건, 전용 MariaDB 전체 144건이 통과했다. [상세 조건 및 테스트별 결과](revalidation/duplicate-recruitment-2026-10-15.md)를 참고한다. 이전 재검증 변경을 포함해 아직 로컬에만 반영한 결과다.

## 2026-10-15 인증·CSRF 재검증

demo의 Basic 허용 및 demo 이외(test+prod)의 정상 Basic 자격증명 거절을 확인했다. 실제 내장 Tomcat HTTP 요청과 쿠키로 로그인 시 JSESSIONID/CSRF 원본 토큰 갱신, 로그아웃 후 이전 세션 재사용 차단, SUSPENDED/WITHDRAWN 계정의 로그인 및 기존 세션 API 접근 차단을 검증했다. 추가 HTTP 테스트 12건이 모두 통과했고 운영 인증 코드는 변경하지 않았다.

누적 전체 결과는 모집글 72 + 참여 72 + 기존 세션 7 + 신규 HTTP 보안 12 + 기존 사용자/컨텍스트 4 = 167건 통과, 실패·오류 0건이다. 외부 DB 조건부 테스트는 환경변수 미설정으로 건너뛰었고 이번 항목에서 MariaDB/MySQL 및 GitHub CI를 다시 실행하지 않았다. [검증 범위·CSRF 비교 기준·테스트별 결과](revalidation/authentication-csrf-2026-10-15.md)를 참고한다. 로컬 변경이며 커밋/푸시/PR 갱신/머지는 수행하지 않았다.

## 2026-10-15 DB 마이그레이션 재검증

신규 DB와 모의 기존 사용자 DB를 구분해 전용 MariaDB 11.4.10에서 Flyway 12.4.0으로 검증했다. 신규 DB는 V1 SQL → V2 SQL, 모의 기존 DB는 현재 사용자 JPA 스키마/합성 데이터 → 구조 대조 및 임시 정합화 → baseline 1 → V2 SQL 순서다. 기존 행·ID·자동 증가값 보존과 새 FK 연결, 모든 엔티티 validate 및 migration 재실행 0건을 확인했다.

JPA가 만든 refresh_token.revoked의 BIT(1)와 V1 BOOLEAN(TINYINT(1)) 차이를 실제 모의 DB에서 발견했다. V1/V2와 운영 설정은 수정하지 않고 임시 DB에만 정합화를 적용해 검증했다. 누락된 테이블이 있어도 baseline·V2·Flyway validate는 통과할 수 있다는 음성 테스트도 추가했다.

마이그레이션 7건과 기존 H2/HTTP 167건을 함께 실행해 총 174건 통과, 실패·오류 0건이다. 기존 외부 DB API 계약은 별도 환경변수 미설정으로 건너뛰었다. MySQL 및 GitHub CI는 이번에 실행하지 않았다.

실제 팀 DB DDL/접속 정보는 아직 없다는 사용자 확인에 따라 **실제 스키마 대조·실제 복제본 리허설·실제 적용은 미완료**다. 신규/모의 DB 성공을 실제 DB 적용 완료로 간주하지 않는다. [이번 결과](revalidation/db-migration-2026-10-15.md), [자료 확보 후 적용 절차](db-migration-existing-users.md), [읽기 전용 조사 SQL](../scripts/inspect-user-schema.sql)을 참고한다. 커밋·푸시·PR 갱신·머지는 수행하지 않았다.

## 2026-10-17 PR 제출 전 확인

누적 재검증 변경을 기존 codex/post-api 브랜치의 PR #12에 추가하는 제출 대상이다. 위 2026-10-15 보고서의 로컬/미푸시 표시는 각각 검증한 당시의 상태를 기록한다.

`gradlew test bootJar --rerun-tasks --no-daemon --console=plain`으로 캐시 재사용 없이 기본 테스트 167건과 실행 파일 빌드를 다시 수행했고 모두 성공했다. 외부 DB API 계약 및 마이그레이션 선택 테스트는 이번 실행에서 건너뛰었다. MariaDB 계약 144건과 마이그레이션 7건은 위 2026-10-15의 별도 실행 결과이며, 제출 당일 재실행이나 MySQL 결과로 표시하지 않는다.

실제 팀 사용자 DB 자료 미확보 및 학교 SSO/실제 SMTP/배포 환경 미검증 범위는 유지한다. V1/V2 SQL·운영 DB 설정·기존 CI 구성은 이번 재검증에서 변경하지 않았다. PR 갱신 후 CI 결과는 GitHub Checks에서 확인하며 main 병합·배포는 이 제출에 포함하지 않는다.

## 2026-10-28 주간 모집글·참여 API 재검증

최신 origin/main `b79ca2a`에서 새 브랜치 `codex/revalidate-post-participation-20261028`로 시작했다. 모집글·참여 코드는 기존 제출 `c8bc537`과 동일했다. 이전 PR의 로컬/미제출 표시는 과거 실행 당시의 기록이며, 이번 작업은 닫힌 PR을 갱신하지 않는 별도 제출이다.

추가 검증에서 지원하지 않는 Accept로 오류 JSON이 누락되고, 변경 요청은 406 응답에도 커밋되는 문제를 실제 HTTP와 DB에서 재현했다. 두 컨트롤러에 JSON 응답 형식 조건을 선언해 실행 전 거절하고, 공통 오류 처리기는 JSON Content-Type을 명시했다. 시간 정책·인증 인계·기존 DB 마이그레이션은 변경하지 않았다.

25건의 회귀 사례를 추가했다. 전체 H2/HTTP 192건과 실행 JAR 빌드가 통과했다. 기본 실행에서 외부 DB/마이그레이션 조건부 테스트 134건은 건너뛰었으며, 이를 통과 건수에 포함하지 않았다. 이어 전용 MariaDB 11.4.10/InnoDB에서 모집글 83 + 참여 85 = 168건을 실행해 실패·오류·skip 0건을 확인했다. 실제 행 잠금 대기 관찰, 경합 처리 순서, 양쪽 테이블 롤백을 포함한다. [주간 재검증 보고서](revalidation/post-participation-2026-10-28.md)에 항목별 근거를 기록했다.

일반 모집글 물리 DELETE는 기능정의서 POST-007에 따라 미제공이며 405/데이터 보존을 확인했다. 관리자 soft delete, 수동 마감, 모집 취소는 서비스 수준 검증만 완료했고 연결 HTTP API는 현재 미구현이다. 실제 팀 DB, MySQL 8.4 및 배포/프론트 연동 완료로 표시하지 않는다. main 병합·자동 머지·배포는 수행하지 않는다.
